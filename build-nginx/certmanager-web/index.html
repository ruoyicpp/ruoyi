Developer Documentation

Does this project need a database?

Current version does not require MySQL, PostgreSQL, Redis, or any external database. Data is stored under the path specified by --path, defaulting to .lego.

  • .lego/accounts/: ACME account information and account private keys
  • .lego/certificates/: certificate files, private keys, issuer certificates, and metadata
  • .lego/credentials.json: saved DNS provider credentials

HTTP Validation

HTTP validation is suitable for normal domains like example.com and www.example.com. It does not require DNS API keys.

Requirements:

  • The domain must resolve to the current web server.
  • Port 80 must be publicly accessible.
  • CertManager must be able to write to the website root directory.
  • The Webroot must match the actual website root configured in Nginx/Apache.

Example Nginx root:

root /var/www/example.com;

Then Webroot should be:

/var/www/example.com

Wildcard domains such as *.example.com cannot use HTTP validation.

DNS Validation

DNS validation is required for wildcard certificates and is also useful when the website is not on the same server. It requires DNS provider API credentials so CertManager can create and delete ACME TXT records automatically.

Tencent Cloud

TENCENTCLOUD_SECRET_ID TENCENTCLOUD_SECRET_KEY

AliDNS

ALICLOUD_ACCESS_KEY ALICLOUD_SECRET_KEY

Cloudflare

CF_DNS_API_TOKEN

Saved Credentials

To avoid asking users to enter API keys every time, add credentials in the page. Users can then select saved credentials when requesting certificates.
